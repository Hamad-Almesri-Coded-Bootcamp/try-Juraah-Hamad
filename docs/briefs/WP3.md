## WHAT TO BUILD
- **Gating, three places (ROLES.md).** (1) `proxy.ts`: for `/[locale]/app/**` require `patient`; `/care/**` require `caregiver`; `/clinic/review/**` require `reviewer`; `/clinic/audit/**` require `admin`; `/clinic` and `/clinic/choose` require a clinic role or no session (X0 is the clinic sign-in); `/invitation` requires a session (pending-only or any role holding a pending invitation); `/gate` requires a session; no session → `/[locale]/signin` (or `/[locale]/clinic` for clinic paths); a `pendingInvitationOnly` session on any path other than `/invitation` → `/[locale]/invitation`. Read the cookie exactly as D-005 defines it; never trust anything else in it. (2) Every shell layout calls `requireRole` server-side and renders nothing for the wrong role (redirect). (3) The data layer already refuses (WP1). Being unlisted is filing, not security: gate `/clinic` exactly like the others.
- **A0 `/[locale]/gate`.** Server component: `getSession()` → redirect per the SCREENS row (none → signin; pending-only → invitation; patient with `onboardingCompleted:false` → `/app/setup`; patient → `/app`; caregiver → `/care`; reviewer → `/clinic/review`; admin → `/clinic/audit`; two roles with no remembered choice → `/signin/choose` or `/clinic/choose`). Renders `LoadingState` while it decides; never blank.
- **App bar + language switch (G2).** `LanguageSwitch` is a quiet `Button` in the app bar's action slot on every screen and in L1's header (bundle a reuses it): swaps the locale segment with `withLocale(pathname, other)` keeping the rest of the path and query, and, for a signed-in patient, calls `updateSettings(patientId, { language })`; for other roles it only swaps the segment. Numerals and direction follow the new locale automatically.
- **Patient shell.** `TabBar` with four items (`home`, `capsule`, `shield`, `settings` icons; labels from `shell.ts`), `href` per item, active from the pathname; content cap `--content-max` at ≥1440; side rail ≥834; a `MoreMenu` page at `/[locale]/app/more` listing Refill · Calendar sync · Notifications & messaging · Caregivers · Activity · Settings · Profile · Help (G8 order) as `MenuRow`s, plus the role switch row when `getRoleOptions()` returns two roles, plus the quiet pending-invitation notice (one `MenuRow`, relationship tone → `/invitation`) when `getPendingInvitationsForSubject()` is non-empty. **No write control of any kind lives in the shell chrome.**
- **Caregiver shell.** Three items (Today · Medicines · More); `CaregiverBanner` on every screen: "viewing <patient first name>'s record" from `getCaregiverLink`; More: Activity · Profile & notifications · Help, plus the role switch when two roles. **No settings item, no write control, nothing the patient shell lacks a counterpart for.**
- **Clinic shell.** Two destinations (Review · Audit) — the `TabBar` items a reviewer sees are built from **their** roles: reviewer-only → Review only; admin-only → Audit only; both → both (a bar is never filtered down, it is built from the role set, `TabBar.md`). Simulated-role `ContextBanner` on every clinic screen. Sign-out control at the bottom of the rail (a quiet Button at phone width in the app bar action slot, per CR-020). Role switch between reviewer and admin from the rail when both roles are held.
- **Role switch.** Calls `chooseRole(option)` then navigates to that shell's home; never `signOut`. Cross-fade only (no slide) — leave motion to CSS, `prefers-reduced-motion` respected.
- **Sign out.** `signOut()` then `router.replace` to `/[locale]` and `history` cleared of the shell (assert in e2e that Back does not return to a shell page).
- **H1/H2/H3.** H1: `EmptyState` + one Button to the current shell's home (from `getSession`) else L1. H2: `ErrorState` with retry (`reset()`) and a way back; `global-error.tsx` the same without the shell; **no error code, no blame**. H3: `/offline` shows the last known data via `readLastKnownSnapshot` when any, with the `asOf` line (formatted with `i18n/format`), the `ContextBanner` lastKnown variant, and a refresh Button; the same `LastKnown` wrapper is exported for list screens' failed-refresh state.
- **Placeholders.** One per missing route, all through `RoutePlaceholder`. They must pass guards (copy from `shell.ts`), render inside the right shell, and be replaced by bundles without touching the layout.
