## WHAT TO BUILD (per SCREENS.md, which wins over this summary)
- **F0** (`/invitation`, no shell): pending state shows patient **first name** + claimed relationship, exactly what accepting shows, exactly what it never allows, "the patient will be told" — from `getInvitationForConsent`'s five fields **and nothing else**; accept/decline `size=lg fullWidth`, **equal size and weight** (primary + secondary tone is the one permitted difference per the board). Accepted → short confirmation → the caregiver shell (or A1b for a dual-role user, per the session `acceptInvitation` returns). Declined → plain acknowledgement, a way out, nothing revealed. Expired/cancelled → says so, no action. `?id=` selects among multiple pending invitations (a signed-in patient answering a notice returns where they were). **Before acceptance nothing else is loaded or loadable — no other data function may appear in this screen's module graph** (assert it in a unit test).
- **F1**: the relationship list as `MenuRow`s — pending (cancel) · active (accepted date, revoke) · declined · expired — **all neutral, no badge/dot/warning colour** (G10). Invite sheet step 1: Civil ID entered once + name-known-by + relationship; step 2: `lookupMaskedName` → masked name (via `lib/format/maskedName.tsx` — **first + family name full, each middle name initial + exactly three asterisks**) with نعم/لا — or, for a Civil ID with no account, the **identical "invitation created" outcome** (same shape, same timing, never revealing non-existence). Cancel and revoke each confirm in a Sheet naming the consequence. After invite: back on the list, "awaiting acceptance".
- **F2** (`/care` + `/care/medicines`): B1/B2 content read-only under the banner; patient tracking off → the same plan and the same one-line explanation the patient sees, **never more**; the danger alert shown, opening your read-only alert detail. **Zero write controls — absent, not disabled.**
- **F3**: prescription detail (B3's content minus every action), alert detail (C2's content; opening never changes state), activity feed (E2's content) — composed from the ui components per the `CaregiverDetail` board and the B3/C2/E2 SCREENS rows (their bundles land later; the lead checks parity at their gates — note any interpretation you take).
- **F4**: own name · identity line per CR-001 (no Civil ID) · linked patient first name + since when (`getCaregiverLink`) · own browser-notification four states and own chat link (**alerts only, never check-ins** — say so in copy) via the notification functions with `subjectType:'caregiver'` · **unlink myself** (Sheet confirm; says the patient can re-invite) · sign out via shared `SignOutButton` · **no Settings row**.
- **F5**: static copy from your catalogue: what a caregiver can and cannot see · cannot record doses or change anything · what to do on a danger alert (contact the clinic; never change medication) · how to be re-invited.
