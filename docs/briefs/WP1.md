## WHAT TO BUILD — precisely

### 1. `types/contracts.ts`

### 2. The seam
**No Civil ID crosses the seam.** No function returns a `Patient`, `Caregiver` or `Account` record whole: define view types in `types/views.ts` (`PatientView = Omit<Patient, 'civilId'>`, `CaregiverView = Omit<Caregiver, 'civilId'>`, …) and return those; `civilId` is an argument to `signIn`, `lookupMaskedName` and `inviteCaregiver` only and is never echoed back. `lib/session/**` may import the mock store (guard 3 exempts it; it is part of the seam).

`lib/data/api.ts` is `export interface DataApi { … }` with **exactly 50** method signatures, each on its own line starting `  name(`, in the appendix's groups, with the appendix's argument names and return types (guard 4 and `notes-check.ts` parse this form). `lib/session/api.ts` likewise, `SessionApi`, 5 methods. `lib/data/index.ts` and `lib/session/index.ts` are `'use server'` modules exporting one async function per method, typed against the interface (`export const getPatient: DataApi['getPatient'] = async (…) => store.…`). No other module in the repository outside `lib/data/**` and `lib/session/**` may import `lib/data/mock/**` (guard 3).

### 3. The mock store (D-002, owner's two conditions)
`lib/data/mock/store.ts`: **a module-level singleton** built from `seed.ts` + the schedule generator, with an exported `reset()` that rebuilds it from the seed; every unit test calls `reset()` in `beforeEach`. Mutations (`acceptInvitation`, `requestRefill`, `startMessagingLink`, `updateSettings`, `revokeCaregiver`, `cancelInvitation`, `submitReviewDecision`, …) change the singleton **and append an `AuditEvent`**; they never change a `Dose.status`. No client component reads the store — it is reachable only through `lib/data/index.ts`. Dev-only fault and fixture switching (`loading`, `error`, `offline`, and fixture states) is a cookie `jurah.dev` read **only** inside `lib/data/mock/faults.ts`; nothing else branches on it; it is inert unless `NODE_ENV !== 'production'`.

Every patient-scoped function takes the session into account (ROLES.md "Enforcement", point 3): it returns nothing (`null` / `[]`) unless the session is that patient, an **`active`** caregiver linked to that patient, or a reviewer with a queue item for that patient. A `pendingInvitationOnly` session gets nothing from any function except `getPendingInvitationsForSubject`, `getInvitationForConsent`, `acceptInvitation`, `declineInvitation`. `getInvitationForConsent` returns `{ id, patientFirstName, relationship, status, expiresAt }` **and nothing else**.

`updateSettings` accepts only the seven permitted keys and refuses `adherenceCheckInEnabled: true` unless the patient's `MessagingLink` is `connected`. `lookupMaskedName(civilId)` returns `{ maskedName }` for an `Account` holder and `{ maskedName: null }` otherwise, **same shape, same code path length, same simulated delay**. `inviteCaregiver` for a Civil ID with no account creates a `pending` row and says nothing about the account. `signIn` never returns or stores a Civil ID; `Session` never carries one.

### 5. The schedule generator (`lib/schedule`)
Pure functions, no clock other than `REFERENCE_NOW`. `generateDoses(prescription, patientTrackingOn)` returns `[]` unless `startDate` is present and `doseTimes.length === frequencyPerDay` (CR-002 invariant 2), and `[]` for `discontinued` after `discontinuedAt` and for `needsReview`/`returned` records. `daily` and `alternate_day` (`other` generates nothing and is reported). Each dose carries `tracked` from the patient's `adherenceCheckInEnabled` at generation, `source: 'seed'`, `status: 'upcoming'` — except سارة's five recorded doses, which are the seed's stated statuses with `source: 'adherence_agent'` and `recordedAt` (these are **overlays applied inside the seed module**, never a status computed from the clock). Nothing ever sets `missed` from time passing. Depletion: `remaining = totalQuantityDispensed − doses scheduled since dispenseDate × dosePerAdministration`, `daysRemaining` from the daily consumption, `null` when no dispensing.

### 6. `lib/format/maskedName.tsx`
`maskName(fullName): string` — first and family name in full, each middle name as its initial + `***` (always three), two-part names unchanged, and `MaskedName` rendering `body-strong` text with the asterisk runs `aria-hidden` and an accessible name that reads the visible parts (CR-021). Honorific prefixes (`د.`, `م.`) are not a name part. Tests: the seed's nine examples verbatim, plus none / one / several middle names.

### 7. i18n
`i18n/index.ts` merges `shell`, `vocabulary`, `session`; keep `t(entry, locale)`. `i18n/format.ts`: `formatNumber`, `formatTime` (HH:mm), `formatDate`, `formatDayLabel`, all taking a `Locale`; Arabic uses **Arabic-Indic digits** as every Arabic board does (`٨:٠٠`, `٥٠٠`) via `Intl` with `-u-nu-arab`, English uses Western digits; times keep `HH:mm`; numerals never mirror. `i18n/copy/vocabulary.ts`: the four dose-status words, two sector words, three review-state words, three severities, the six actor labels and the 26 event-type labels for the audit log (human labels; CR-010: only X1 shows the literal strings, beside these), every entry `placeholder: true`, Arabic starting from `design/ds-fallback-strings.json` and the boards, English drafted. `i18n/copy/session.ts`: the sign-in outcome sentences (A1's four states, `no_claims` **one** entry used for both the no-account and the declined/expired case), role labels, all `placeholder: true`.
