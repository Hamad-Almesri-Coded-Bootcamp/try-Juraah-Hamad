## WHAT TO BUILD (per SCREENS.md, which wins over this summary)
- **E1**: off → what subscribing gives, one subscribe action (`enableCalendarSync` + `updateSettings`) · on → the per-patient `webcal://` link in a `CopyField`, short add-to-calendar instructions, the one-directional line (the calendar never writes back). The webcal URL is the one place a token-bearing URL is shown — the spec requires it; show it exactly as the data layer returns it, never constructing it in the screen.
- **E2**: patient-scoped `AuditEvent` rows via `ActivityRow`, reverse chronological; each row links to the thing it happened to (a prescription → B3, an alert → C2, a caregiver event → F1, settings → E3 — only where a destination exists); masked names via the formatter; read-only; empty state. Wrap in `LastKnown`.
- **E3**: **exactly** these controls and no others (CR-011: no channel Select; no language control — the switch lives in the app bar): adherence tracking on/off (`Toggle`) + check-in frequency (`ChoiceGroup`) · refill alerts (`Toggle`) · calendar sync (`Toggle`, state shared with E1) · optional contact phone (`TextField`). The adherence toggle with no `connected` chat: renders off with a one-line explanation and a link to E5 — flipping it routes to E5 rather than failing (the data layer refuses `adherenceCheckInEnabled: true` without a connected link; never show that as an error). Turning tracking off confirms in a `Sheet` naming the consequence: check-ins stop, new statuses stop recording, history kept.
- **E4**: static copy from your catalogue, per the row's topic list: how the app works · check-ins are optional and answered in the chat · a dose instruction looks wrong · a safety alert appears · contacting the issuing clinic or pharmacy · no clinical advice, ever.
- **E5**: **Browser section** — `default`: what the browser will ask, one enable action (`requestPushPermission`) · `granted`: on, the alert types listed, send-test (`sendTestNotification`), disable (`disablePush`) · `denied`: neutral tone, the re-enable steps for the browser, never a nag · `unsupported`: says so; **iOS Safari not installed → the add-to-Home-Screen steps** (`getPushCapability().iosNeedsInstall`). **Chat section (optional)** — not connected: neutral, what connecting gives, one connect action (`startMessagingLink`) · waiting: the pending state; **the one-time token is never shown** (rule 7 — the mock's link flow works without displaying it; the bot handle from `config.BOT_HANDLE` is shown, labelled simulated in your catalogue's words) · connected: since-when, send-test (`sendTestMessage`), disconnect via `Sheet` naming the consequence (`disconnectMessaging`) · expired/failed: says so, retry. **Neither section blocks navigation; no state renders as an error or warning tone** (G10) — `InlineNotice` never in warning tone for an off state. **G12: nothing here builds or requests a notification with an action.**
