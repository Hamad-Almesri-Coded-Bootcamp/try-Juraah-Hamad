`grep -o` counts one hit per *occurrence*, over `agents` and `lib` combined, with no exclusions. Guard
P sums every occurrence on a line it counts at all — the printed list still shows one entry per
line, not per occurrence, and on this tree every counted line holds exactly one, so the two totals
never visibly differ — over the app dirs (`app`, `components`, `features`, `lib`, `i18n`,
`types`, `public`, `design`) and `agents/` as two separate tallies, and only over `.ts`/`.tsx`/`.js`/
`.json` files — so it never sees `agents/README.md` (a `.md` file: the grep's line 102 above). It also
excludes:

- the identifier's own declaration, `export const TO_BE_SUPPLIED = …` (`lib/config.ts:41`, not shown
  above because the earlier exclusion filter already dropped it) — a definition is not a missing value;
- a bare reference with no `=`/`:` immediately before it — an `import { TO_BE_SUPPLIED }` (`seed.ts:16`)
  or a comparison/comment that merely *mentions* the name (`seed.ts:11`, `:271`) is not itself a value
  that is missing, only the assignments that use it are (`lib/config.ts:56`, `seed.ts:121/274/280/289`).

That leaves app 5 (`lib/config.ts:56` and four lines in `lib/data/mock/seed.ts`) and agents 12 — the
list `npm run guards` prints — for 17 counted markers, against the grep line's 23 raw occurrences; the
six-occurrence gap is exactly the declaration line's two occurrences, the import, and the three
comment/README mentions above.

## The limit that F4's pending state cannot be seen under the mock

`tests/e2e/caregiving.spec.ts`'s new per-locale F4 read-only test (سارة، cg-02, active, no link row
yet) posts nothing — it only proves the *connected* state and the row itself carry no token, because
the mock backend confirms a mint in about 50 ms (the existing round-trip test's own comment says so).
A `pending` page — the one moment a real, long-lived token would actually be sitting in a link row
behind the screen — settles to `connected` before a scan could ever catch it *not* leaking. **J1 is
what actually covers the pending state**: it runs on production, where the token is real and the
confirm is not instant, and both the network panel's `Location` and the page source are scanned then.
