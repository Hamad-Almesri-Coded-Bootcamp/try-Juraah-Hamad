## What changed

| File | Change |
|---|---|
| `agents/lib/adherence.js` | **Step 1 (TC-RS-03).** `discontinued_by_doctor` never writes by itself any more. A typed report returns outcome `confirm_discontinue` with `writes: []` and `stopOptions` (one `{ prescriptionId, label }` per the patient's ACTIVE prescription, read from the new `prescriptions` input). New `stopTapData(rxId)` (`s:<rxId>`, checked against `/^[A-Za-z0-9_-]{1,48}$/`, `Buffer.byteLength <= 64`) and `parseStopTap()` (`s:<id>` or the fixed `n:none`, checked first so it can never parse as an id). A stop tap on one of the patient's own active prescriptions gives outcome `discontinue` and exactly one `recompute` write with a **fixed** `discontinuedReason` (callback data has no room for the patient's quote — reserved as CR-093 if the owner wants it kept). `n:none` gives `discontinue_none`, no write. An unknown/foreign/inactive id gives `no_dose`. A caregiver's stop tap is refused like any other caregiver write attempt. New `buildStopOptions()` builds the Telegram messages (one "Stop `<drug>`?" message per option, ONE button each, plus a "none of these" message). New ar/en reply strings (`confirm_discontinue`, `discontinue_none`), Kuwaiti register, no em dash. **Step 2 (TC-AD-12).** New pure `readDates(sentAt)`: `[previousDate, today]` when the reply's Kuwait hour is 0–2, else `[today]` — used by `build.js`'s ROUTE for TYPED replies only (a tap already names its own dose and check-in day). `candidateDoses`/`decide()` needed no change: each dose's `scheduledAt` is an absolute instant, so a merged two-day array already sorts and filters correctly. `buildCheckIn()` gained an optional `referenceDate`: a dose whose own Kuwait date differs is prefixed "أمس"/"Yesterday" in its message, so an across-midnight "which dose" question never reads as the wrong day. **Step 3.** New pure `planCheckIns({ eligibility, dayIndex })` — the daily check-in's existing plan-time filter (no chat id; the `every_other_day` parity), factored out so the new skip-log node can recompute the same thing independently of the node that actually plans. **Step 4.** `decide()` takes `trackingOn` (tri-state) and `caregiverVerified` (tri-state). Where it would answer `no_dose` because nothing is open AND `trackingOn === false`, it answers a new `tracking_off` outcome instead (new reply naming the app's existing "Dose check-ins" group, `i18n/copy/ambient.ts` `e3GroupCheckIns` — no copy invented). `trackingOn` absent/`true` keeps today's `no_dose` reply exactly. Where a chat claims to be a caregiver but `caregiverVerified === false`, `decide()` answers `caregiver_unverified` with `reply: null` (nothing sent) instead of the normal refusal — `caregiverVerified` unset/`true` keeps today's plain `caregiver_refused`. **Step 5.** The food-timing separator in `buildCheckIn` changed from " — " (U+2014) to " · ", closing the file's one em dash (AP-17, scoped to this file only per the run's instructions). |
| `agents/scripts/build.js` | ROUTE: parses a callback into a dose tap (`d:`) or a stop tap (`s:`/`n:none`) — never both — and a callback NEVER sets `needsModel` any more (previously an unparseable callback with non-empty text reached Gemini; fixed). Computes `dates` via `readDates` for a typed message, exposes `prevDosesUrl` (null outside the midnight window), `prescriptionsUrl`, `alertRecipientsUrl`, and passes `trackingOn` straight through from the relay body (tri-state). DECIDE: fetches `backend: active prescriptions` and, conditionally, `backend: doses of the previous day` and `backend: alert recipients (caregiver check)`; fails CLOSED (`outcome: 'refused'`) for a patient reply when doses, prescriptions or a REQUESTED previous-day fetch did not come back 200 — never a silent fall-back to today's doses alone. Re-verifies an alleged caregiver against `alert-recipients` and passes `caregiverVerified` into `decide()`. REPLY: sends nothing when the decision's `reply` is `null`; adds the stop-option messages for `confirm_discontinue`; marks yesterday's dose in the `ask_which` messages via `referenceDate`. Five new nodes on the adherence branch of `agent-telegram-inbound` (`backend: active prescriptions`, `after midnight?`, `backend: doses of the previous day`, `a caregiver chat?`, `backend: alert recipients (caregiver check)`), plus four new **log** Code nodes (never a chat id, never message text): `log: non-active caregiver (deterministic)` (fanned from `decide (deterministic)`), and one `log: failed Telegram send (…)` fanned out after each of the three Telegram send nodes (`failedSendLog()` factory, reads `$input.all()` for `.error` items left by `onError: continueRegularOutput`). `agent-checkin-daily`: `CK_PLAN` now calls the shared `planCheckIns`; new `log: skipped patients (deterministic)` (fanned from `backend: who is eligible`, so it runs even when the plan is empty) recomputes the same plan-time skips and additionally reads `backend: doses of the day`'s own results for a refused fetch or an empty day; two more `log: failed Telegram send (…)` nodes after its two send nodes. |

New scenarios (see Proof) for TC-RS-03 (ask, tap, none/unknown/caregiver), TC-AD-12 (midnight fetch required + fail-closed, cross-day ask, 03:00 boundary), TC-AD-09/CR-092, TC-AD-16, G10 (failed send log), TC-AD-08 (skip log, including "runs on an empty plan"), and a static check that every named log node exists and is wired, plus that `agent-checkin-daily` makes no POST and no `/doses/`/`/schedule/` call. |
