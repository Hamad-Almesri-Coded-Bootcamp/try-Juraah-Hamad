## What changed

- `agents/knowledge/src/extraction.js` (the shared core - also used by the app's `agent-extraction`
  workflow): added a caption input. `RESPONSE_SCHEMA` gains `captionConflicts` (not in `confidence`,
  not in `required`); PROMPT gains rule 10; `toPrescriptionBody` reads `args.caption` and, when a
  caption is attached, a field named in `model.captionConflicts` is left unset and flagged exactly
  like a low-confidence reading. A caption with no `captionConflicts` answer is unknown, not
  agreement, so it flags all five FLAGGABLE fields (fail closed). With no caption, the path is
  byte-for-byte what it was - the app's own call is unaffected.
- `agents/lib/extraction.js`: reduced to the Telegram channel's own parts, built on the core via
  `require('../knowledge/src/extraction.js')`. Adds `readVision(res)` (a non-200, a non-`STOP`
  `finishReason`, unparseable JSON, or an answer with no boolean `isPrescription` are each a named
  reason - `vision_http_<status>`, `vision_finish_<reason>`, `vision_unparseable`,
  `vision_answer_malformed` - never silently `not_a_prescription`) and `extractFromTelegram({patientId,
  res, caption, fileProblem})`. `extractionReply` gains an `unreadable` branch (Kuwaiti register,
  CR-079) ahead of the generic failure branch.
- `agents/scripts/build.js`: `inline()` also strips the core's `require` line and throws if one
  survives inlining (mirrors `agents/knowledge/scripts/build.js`'s `strip()`); `EXTRACTION` now
  inlines the core then the Telegram file; `EX_REQUEST`/`EX_VALIDATE`/`EX_REPLY` (the
  `agent-telegram-inbound` Code nodes) are rewired onto `extractFromTelegram`, carrying the caption
  and a named `fileProblem` instead of the old ad-hoc `JSON.parse` + `not_a_prescription` fallback;
  the reply log gains `reason`.
- `agents/knowledge/test/extraction.test.js`: three new TC-EX-06 tests (contradicting caption flags
  the named field; a missing `captionConflicts` answer flags all five; no caption leaves the path
  unchanged).
- `agents/test/extraction.test.js`: rewritten against the core-backed `agents/lib/extraction.js` -
  `SURE` is now every `CONFIDENCE_KEYS` key (17), doseTimes pre-sorted in the fixture (the core does
  not sort). Covers: strength with no unit flagged; a truncated answer (`finishReason: MAX_TOKENS`)
  unreadable and never parsed; an outage (503) unreadable and reads differently to the patient than
  "not a prescription"; a contradicting caption through `extractFromTelegram`; a file-problem
  short-circuit; save-failure/needsReview/clear reply text.
- `docs/DECISIONS.md`: CR-098 appended, marked `PARTIALLY BUILT, timeboxed` with the same owed list
  as below.
- Rebuilt workflow JSON (from the generators, not hand-edited): `agents/workflows/*.json` and
  `agents/knowledge/workflows/*.json`.
