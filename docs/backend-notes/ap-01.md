# AP-01 · Live drift audit and the drift check

## What was built

`agents/scripts/drift.js` (`npm run drift` in `agents/`). Both sides are reduced to one sha-256 per node by the **same** normalisation (`NORMALISE_SOURCE` in the script: ids, positions, credential ids, `versionId` and timestamps dropped; type, typeVersion, parameters with Code-node source and the execution settings kept; CRLF folded). The live side comes from:

- `node scripts/drift.js --snippet`: prints a snippet to run in the n8n page (logged in); it prints the live hashes, which are saved as JSON and passed with `--live <file>`; or
- `N8N_BASE_URL=… N8N_API_KEY=… node scripts/drift.js --api`: reads the live side from the n8n public API.

It **fails** on any differing node, on a committed workflow with no active live counterpart, and on a live `agent-*` workflow with no committed file. A missing input is an error, never a pass. `agents/test/drift.test.js` proves it goes red on a deliberately edited copy, a missing workflow and an unknown one, and stays green for CRLF.

**Live-only config.** `ALEXA_SKILL_ID` and `ALEXA_LINKS` in `alexa request (deterministic)` are set only in the live node (the repository ships them empty, so it fails closed). The normalisation replaces them with a marker before hashing: they are never compared, printed or copied into the repository.
