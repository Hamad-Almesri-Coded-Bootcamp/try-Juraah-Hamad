## One deliberate choice, recorded rather than left silent

`routeInbound` cannot tell an image sent as a Telegram *document* from a PDF sent as a document, because the relay (`lib/messaging/telegram.ts` / `lib/agent/inbound.ts`) forwards a bare `documentFileId` with no mime type at all (confirmed by reading both files; no app change is needed or made here). So a fresh `documentFileId` always enters the same `'photo'` route as an inline photo, and `photoQuestion(mime, buffer)` - run immediately after the file is downloaded, *before* any model call - decides a PDF is `prescription` outright from its mime type (`mimeShortcut`), never spending a Gemini call on it. This reaches the same place the plan's step 2 rule 3 asks for ("a patient's PDF goes straight to extraction"), one hop later than a literal reading of "decided before download" might suggest. Proven by `agents/test/orchestrator.test.js` ("a PDF sent as a document is decided as prescription without asking the model at all") and `agents/scripts/check.js` ("a PDF sent as a document is decided prescription from its mime type alone, never asked to the model").

**One thing the root gate found, fixed here (outside this package's own file list).** Running the full root `npm run verify` surfaced a real cross-package gap: `tests/unit/agent-webhooks/core.test.ts` ("every appOutcome the real agent produces is read back unchanged") runs the real, now-changed `travelCheck` and asserts `readDrugCheck` (`lib/agent-webhooks/core.ts`) returns every outcome byte-for-byte - it did not know about `cannot_verify` yet, since `readDrugCheck` itself is PR #13/AP-11a's file to update, not this package's. The test is updated to assert the documented fallback (`could_not_identify`, matching the *next* test in the same file, "anything unexpected is could_not_identify") for `cannot_verify` specifically, and byte-for-byte unchanged for every other outcome, with a comment naming PR #13 as the closer. Left alone, this would have left the root gate red for a reason CR-095 already called safe; fixed narrowly instead of reported and walked away from. `npx vitest run tests/unit/agent-webhooks/core.test.ts` -> 19/19 pass.

**One thing this branch does not change, on purpose.** `agents/knowledge/scripts/build.js`'s `TC_CHECK` (Travel Check's own generator, outside this package's reserved files) already answers a backend-unreachable profile with a hardcoded `{ verdict: 'could_not_identify', reason: 'profile_unavailable', appOutcome: { kind: 'could_not_identify' } }` - a different claim from `VERDICT.CANNOT_VERIFY` ("we know the profile, this specific pair is outside our data"): here we do not even know the profile. Its test in `agents/knowledge/scripts/check.js` ("profile unreadable (backend 503)") is left asserting `could_not_identify`, unchanged - checked by hand against `build.js`'s source before deciding not to touch it. **Since superseded on main by AP-11b** (PR #20): that case now answers `cannot_verify` / `profile_unavailable`; see "The merge with AP-11b" below.
