# AP-02 · Voice back inside rule 1

**Why.** Plan finding 1: Alexa could record dose statuses on the live demo. The agents entry CR-070 put a
`VOICE_RECORDS` switch and a write branch in `agent-alexa` (off in the repository, on in the live node),
against CLAUDE.md rule 1 and TC-AD-14/15. Gate A decision D1 (CR-073): off, and the write path removed.
**CR-070's recording is reversed by CR-073.** The as-built choices are CR-101.

## What changed

| File | Change |
|---|---|
| `agents/scripts/build.js` (agent-alexa) | Deleted the `VOICE_RECORDS` switch and eight nodes: `plan (deterministic)`, `record now?`, `one item per write (deterministic)`, `backend: record the status`, `recomputes (deterministic)`, `any recompute?`, `one item per recompute (deterministic)`, `backend: recompute`. `needs the schedule?` now goes straight to `speak (deterministic)`, which reads the two GETs itself (as before CR-070). Free talk and `quickFreeTalk` unchanged. |
| `agents/lib/voice.js` | Write-path plumbing only: `parseAlexaRequest` no longer reads `session.attributes.pending` (and a "yes" no longer fetches doses), `alexaResponse` no longer writes session attributes, `AMAZON.YesIntent` maps to the screen topic `unclear` (it was `record`). | `agents/test/voice-actions.test.js`, `agents/test/voice.test.js` | Recording tests replaced by tests of the fixed line, the button choice, the outage fallback, the replayed "yes", and the absence of the write functions. |

Without it an Arabic record request on a real Echo falls to `AMAZON.FallbackIntent` (the help text, no fixed line, no buttons), because the ar-SA model has no `FreeTalkIntent`. The live skill needs its model rebuilt from this file (owed below). |
| `agents/README.md` | Voice section (including the Arabic `RecordDoseIntent`), the setup step that rebuilds the model, and the live-only config note. |
| `docs/DECISIONS.md` | CR-101 (as built). |
